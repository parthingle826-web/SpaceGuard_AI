> ⚠️ **ACADEMIC SIMULATION DISCLAIMER:**  
> SpaceGuard AI is an educational simulation and decision-support architecture. All telemetry readings and anomaly events are synthetically modeled for academic machine learning research and do **NOT represent real NASA or operational spacecraft mission data**. Recommendations generated by the system are operator advisory guidance, never autonomous control commands dispatched to real spacecraft.

---

## 1. Project Overview
SpaceGuard AI is a full-stack, runnable academic mini-project designed to detect, classify, explain, and mitigate subsystem anomalies across low Earth orbit (LEO) satellites. The system features:

- **11-Channel Telemetry Ingestion:** Continuous monitoring of Battery Voltage, Battery Current, Chassis Temperature, CPU Temperature, Solar Panel Voltage, Solar Panel Current, Power Consumption, Cabin Pressure, RF Signal Strength, Comm Status, and Radiation Flux.
- **3-Model Machine Learning Engine:** Empirical comparison of **Decision Tree (CART)**, **Support Vector Machine (RBF Kernel)**, and **Extreme Gradient Boosting (XGBoost)** trained on identical stratified splits.
- **Extensible Architecture:** Designed with an extensible `MODEL_REGISTRY` interface, allowing new algorithms (e.g., Random Forest, LightGBM) to be plugged in with a single configuration line.
- **Feature Explainability & Attribution:** Identifies the prominent telemetry deviations driving predictions, accompanied by hedged, transparent explanations for human operators.
- **Rule-Based Decision Support:** Generates structured advisory recovery procedures keyed on anomaly category and severity level (Normal / Warning / Critical).
- **Dark Mission-Control Dashboard:** Built with Bootstrap 5 and Chart.js featuring real-time telemetry sparklines, subsystem health matrices, alert banners, simulation controls, and failure injection.

## 2. Technology Stack
- **Frontend:** HTML5, Vanilla CSS3 (custom space-theme design system), JavaScript (ES6+), Bootstrap 5, Chart.js 4.4, FontAwesome 6.
- **Backend:** Python 3.10+, Flask RESTful APIs, Flask-CORS, Python Threading.
- **Machine Learning:** scikit-learn (Decision Tree, SVM, Preprocessing, Metrics), XGBoost.
- **Data Processing:** Pandas, NumPy.
- **Model Persistence:** Joblib (`.joblib` binary checkpoints).
- **Database:** SQLite 3 (ACID-compliant storage for anomaly logs and telemetry stream).

## 4. Dataset & Anomaly Classes
The synthetic telemetry dataset (`backend/data/satellite_telemetry_synthetic.csv`) contains **7,200 observations** sampled at 10-second intervals (spanning 20 hours / ~13.3 LEO orbits). It simulates nominal orbital cycles (sunlit passes vs. eclipse passes) alongside 7 realistic spacecraft failure modes:

| Class Index | Anomaly Category | Subsystem | Injected Failure Characteristics |
| :---: | :--- | :--- | :--- |
| **0** | **Normal** | All Subsystems | Nominal orbital fluctuations across all sensors |
| **1** | **Temperature spike** | TCS (Thermal) | Radiator dissipation degradation ($T > 55^\circ\text{C}$, $T_{\text{CPU}} > 75^\circ\text{C}$) |
| **2** | **Battery voltage drop** | EPS (Power) | Internal cell fault, bus sag ($V_{\text{bat}} < 23\text{V}$, high current draw) |
| **3** | **Current surge** | EPS (Power Distribution) | Distribution harness transient surge ($I_{\text{bat}} > 10\text{A}$, $P > 350\text{W}$) |
| **4** | **Excessive power consumption** | EPS / Payload | Unintended payload load runaway ($P_{\text{load}} > 320\text{W}$) |
| **5** | **Sensor value drift** | Avionics / Transducers | Cumulative linear drift on cabin pressure transducer |
| **6** | **Communication signal drop** | TT&C (Comms) | Downlink carrier attenuation ($RSSI < -100\text{ dBm}$, lock loss) |
| **7** | **Multiple simultaneous abnormalities**| Multi-Subsystem | Space radiation storm causing simultaneous power, thermal, and comm stress |

## 5. Machine Learning Comparative Results
All three models were trained and evaluated on an identical stratified split (5,760 train samples, 1,440 test samples) with random seed 42. Metrics reflect **actual computed results** from `backend/models/metrics.json`:

| Model | Architecture Family | Accuracy (%) | Precision (%) | Recall (%) | F1-Score (%) | Training Time | Inference Latency |
| :--- | :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **Decision Tree** | CART / Trees | 98.12% | 98.11% | 98.12% | 98.09% | 0.103 s | **0.0009 ms / record** |
| **Support Vector Machine** | Kernel Methods (RBF) | **99.44%** | **99.45%** | **99.44%** | **99.44%** | 1.091 s | 0.0259 ms / record |
| **XGBoost** | Gradient Boosted Trees | 99.03% | 99.04% | 99.03% | 99.01% | 2.048 s | 0.0041 ms / record |

### Key Findings
1. **SVM** achieved the highest overall classification accuracy (99.44%) due to the RBF kernel's ability to map non-linear multi-subsystem correlations cleanly into high-dimensional space.
2. **XGBoost** achieved 99.03% accuracy with exceptional noise resilience across all classes.
3. **Decision Tree** delivered the fastest inference latency (0.0009 ms / sample) and provides direct feature importance interpretability (`feature_importances_`), making it an ideal candidate for on-board flight software.

## 6. REST API Reference

| Endpoint | Method | Description | Parameters / Payload |
| :--- | :---: | :--- | :--- |
| `/api/health` | `GET` | Current satellite telemetry snapshot & health score | None |
| `/api/dashboard/stats` | `GET` | High-level KPIs, anomaly counts & subsystem statuses | None |
| `/api/telemetry` | `GET` | Paginated telemetry stream records | `limit`, `offset`, `parameter`, `anomaly_only` |
| `/api/predict` | `POST` | Runs inference on single telemetry JSON or batch CSV | JSON: `{telemetry: {...}, model_name: "XGBoost"}` or CSV file |
| `/api/models/performance` | `GET` | Comparative metrics, confusion matrices & feature weights | None |
| `/api/history` | `GET` | Logged anomaly history from SQLite database | `limit`, `offset`, `severity`, `type` |
| `/api/history/clear` | `POST` | Clears all anomaly history from SQLite database | None |
| `/api/dataset/upload` | `POST` | Validates and ingests CSV dataset into telemetry stream | Form multipart: `file` |
| `/api/simulation/start` | `POST` | Starts real-time orbital simulation background thread | None |
| `/api/simulation/stop` | `POST` | Stops real-time orbital simulation background thread | None |
| `/api/simulation/status` | `GET` | Current running status of simulation engine | None |
| `/api/simulation/inject_anomaly` | `POST` | Injects test anomaly into next simulation tick | JSON: `{"anomaly_type": "Temperature spike"}` |
| `/api/models/set_active` | `POST` | Sets active model for real-time simulation | JSON: `{"model_name": "XGBoost"}` |

## 7. Installation & Quick Start (Windows)

### 1. Clone or Open Workspace
```powershell
cd "d:\AIML_Mini_Project ( SpaceGuard AI)"
```

### 2. Create Virtual Environment & Install Dependencies
```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r backend/requirements.txt
```

### 3. Generate Data & Train Models
```powershell
python scripts/generate_dataset.py
python backend/ml/preprocess.py
python backend/ml/train_models.py
python backend/ml/evaluate.py
```

### 4. Start Flask Server
```powershell
python backend/app.py
```

### 5. Open in Web Browser
Open your browser and navigate to:  
👉 **`http://127.0.0.1:5000/`**
