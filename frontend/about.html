1. Problem Statement & Operational Context

Mission Operations Context

Modern orbital spacecraft generate continuous high-frequency multi-subsystem telemetry spanning electrical power (EPS), thermal control (TCS), attitude determination and control (ADCS), telecommunications, and onboard computing (C&DH). In Low Earth Orbit (LEO), spacecraft experience rapid environmental transitions between direct solar exposure and deep eclipse every ~90 minutes, leading to cyclic thermal and electrical stress.

Traditional ground operations rely heavily on static out-of-limits (OOFL) threshold alarms. These static thresholds often produce high false alarm rates during orbital transitions or fail to detect multivariate, subtle subsystem anomalies (such as sensor drift or compound cross-subsystem degradation). SpaceGuard AI addresses this limitation by deploying machine learning classifiers to distinguish genuine anomalies from nominal orbital fluctuations, compute individual feature attribution, and provide structured advisory decision support to human operators.

4. Machine Learning Methodology & Extensibility

Comparative ML Study

Decision Tree (CART)

Employs recursive binary splitting optimized via Gini impurity. Provides inherent interpretability through decision paths and direct computation of global feature importances (feature_importances_).

Support Vector Machine

Constructs optimal separating hyperplanes in high-dimensional reproducing kernel Hilbert spaces (RBF kernel). Highly effective for isolating non-linear anomaly boundaries. Platt scaling provides calibrated class probabilities.

XGBoost (Gradient Boosted)

Sequential ensemble utilizing second-order Taylor expansion loss gradients and L1/L2 tree regularization. Delivers state-of-the-art multi-class classification accuracy and resilient resistance to telemetry noise.

Extensible Architecture Design (MODEL_REGISTRY):

The machine learning pipeline implements a unified MODEL_REGISTRY dictionary interface. Adding a fourth classifier (such as Random Forest, Logistic Regression, or LightGBM) requires only a single configuration entry in backend/ml/train_models.py without altering evaluation, caching, or inference logic.
